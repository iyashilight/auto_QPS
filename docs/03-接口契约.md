# 03 接口契约（Interface Contracts）

> 适用：所有开发者。以下签名定义在 `src/qps/core/ports/`，是跨模块调用的唯一通道。
> 约定：签名即文档；`...` 表示实现体（由开发者实现）；实现禁止改变签名、语义与异常类型。
> 最后更新：2026-08-03

## 1. 契约总则

1. **端口 = Protocol**：所有端口用 `typing.Protocol` 定义，实现类 `struct` 校验（`isinstance` 或 `runtime_checkable`）；
2. **三要素**：每个方法必须满足「前置条件 / 后置条件 / 异常」三要素，见各方法语义；
3. **不可变**：输入输出 DTO 一律不可变（Pydantic `frozen=True` 或 dataclass frozen）；禁止方法内修改传入对象；
4. **幂等**：所有标注「幂等」的方法，重复调用（同一 ID）必须返回等价结果且不产生副作用；
5. **协程语义**：IO 方法一律 `async def`；纯计算方法允许同步；
6. **异常类型**：只抛 01 文档第 7 节定义的类型化异常；
7. **禁止泄漏**：端口实现禁止向上层暴露实现细节（交易所原始对象、内部缓存等）。

## 2. 数据访问端口（DataProviderPort）

本节的 `get_*` 方法仅保留给明确标记的 legacy/test 兼容实现，不得由生产容器、正式回测或研究 CLI 取得。正式研究使用 §14 的 `PointInTimeDataPort`，所有数据集都必须显式传入 `manifest_id` 与 `decision_time`。

```python
class DataProviderPort(Protocol):
    async def get_bars(
        self, instrument_id: str, interval: str,
        start: datetime, end: datetime,
        data_version: str | None = None,
    ) -> list[Bar]: ...

    async def get_ticks(
        self, instrument_id: str, start: datetime, end: datetime,
    ) -> list[Tick]: ...

    async def get_funding_rates(
        self, instrument_id: str, start: datetime, end: datetime,
    ) -> list[FundingRate]: ...

    async def get_open_interest(
        self, instrument_id: str, start: datetime, end: datetime,
    ) -> list[OpenInterest]: ...

    async def get_mark_prices(
        self, instrument_id: str, start: datetime, end: datetime,
    ) -> list[MarkPrice]: ...

    async def get_features(
        self, instrument_id: str, feature_names: list[str],
        start: datetime, end: datetime,
        feature_version: str | None = None,
    ) -> list[FeatureSet]: ...

    async def get_instrument(self, instrument_id: str) -> Instrument: ...
    def calendar(self, exchange: str) -> list[ExchangeCalendar]: ...
```

语义要点：

- 时间范围 `[start, end)` 左闭右开；`start/end` 必填，禁止无边界查询；
- `data_version/feature_version` 为空时返回**当前默认版本**并在结果中标注；
- 数据缺失不抛异常，返回空列表（由调用方判断），但质量 `SUSPECT` 数据默认过滤，除非显式 `include_suspect=True`（需在扩展方法中支持）；
- `get_bars` 返回结果按 `open_time` 升序；重复调用同一参数必须返回一致顺序（确定性要求）；
- `calendar` 返回 `list[ExchangeCalendar]`，按日期升序；字段定义见 docs/02 §3.1。

## 3. Market Adapter 端口（MarketAdapterPort）

```python
class MarketAdapterPort(Protocol):
    async def connect(self) -> None: ...
    async def disconnect(self) -> None: ...

    async def subscribe_bars(self, instrument_id: str, interval: str,
                             callback: Callable[[Bar], None]) -> str: ...
    async def subscribe_funding(self, instrument_id: str,
                                callback: Callable[[FundingRate], None]) -> str: ...
    async def unsubscribe(self, subscription_id: str) -> None: ...

    async def fetch_historical_bars(
        self, instrument_id: str, interval: str,
        start: datetime, end: datetime,
    ) -> list[Bar]: ...

    def status(self) -> AdapterStatus: ...
```

语义要点：

- 回调在事件循环内同步执行，实现方负责去重去抖与缓冲；回调抛异常只记录不中断订阅；
- `subscribe_*` 返回订阅 ID；`unsubscribe` 幂等；
- `fetch_historical_bars` 用于数据采集（分页/限频由 Exchange Adapter 内部处理）；
- `status()` 返回 `AdapterStatus`，字段定义见 docs/02 §3.2。

## 4. Exchange Adapter 端口（ExchangeAdapterPort）

```python
class ExchangeAdapterPort(Protocol):
    async def connect(self, credentials: Credentials | None = None) -> None: ...
    async def disconnect(self) -> None: ...

    async def request(
        self, method: str, path: str,
        params: dict | None = None,
        signed: bool = False,
        market: Literal["spot", "futures"] = "spot",  # M1.3 新增：市场维度
    ) -> dict | list: ...  # M1.3 变更：K 线等接口返回 list

    async def subscribe(self, channel: str, payload: dict,
                        callback: Callable[[dict], None],
                        market: Literal["spot", "futures"] = "spot") -> str: ...  # M1.3 新增

    async def get_server_time(self) -> datetime: ...
    def rate_limiter(self) -> RateLimiter: ...
    def status(self) -> AdapterStatus: ...
```

语义要点：

- 这是**最低层**端口：负责签名、限频、重连、心跳；业务语义（K 线/订单）不在此层；
- `request` 超时后必须抛 `BrokerNetworkError`（禁止静默）；
- **M1.3 主机路由**：Binance 现货与永续使用不同主机——现货 REST `https://api.binance.com`、永续 REST `https://fapi.binance.com`；现货 WS `wss://stream.binance.com:9443/ws`、永续 WS `wss://fstream.binance.com/ws`；`market="spot"` 走现货主机，`market="futures"` 走永续主机；
- 限频触发抛 `BrokerRateLimitError`，调用方按 retry-after 重试；
- 断线自动重连（指数退避，上限可配置），重连后重新订阅全部 channel；
- 所有返回为交易所原始结构（dict 或 list），规范化在上一层（Market/Broker Adapter）完成。

## 5. Broker Adapter 端口（BrokerAdapterPort）

```python
class BrokerAdapterPort(Protocol):
    async def connect(self) -> None: ...
    async def disconnect(self) -> None: ...

    async def place_order(self, order: Order) -> OrderAck: ...          # 幂等
    async def cancel_order(self, client_order_id: str) -> OrderAck: ... # 幂等
    async def get_order(self, client_order_id: str) -> OrderStatus: ...

    async def get_account(self) -> Account: ...
    async def get_positions(self) -> list[Position]: ...

    def on_execution_report(self, callback: Callable[[ExecutionReport], None]) -> None: ...
    def on_account_update(self, callback: Callable[[Account], None]) -> None: ...

    def status(self) -> AdapterStatus: ...
```

语义要点（Paper 与实盘实现必须一致）：

- `place_order` 幂等：同一 `client_order_id` 重复调用返回同一订单引用，**不得重复下单**；
- 返回 `OrderAck = {client_order_id, broker_ref, status}`；最终状态通过 ExecutionReport 异步到达；
- `cancel_order` 幂等；订单已成交则返回当前状态；
- `on_execution_report`：注册回调处理成交/状态回报；回调必须可重入（实盘 WS 断线重连后会重放部分回报，实现方需按 `event_id` 去重）；
- 交易所拒单必须抛 `BrokerBusinessError`（含结构化 reject_reason）；
- `get_positions` 返回的 mark price 为 null 时由上层补标价（禁止实盘实现伪造）。

## 6. Feature Pipeline 端口（FeaturePipelinePort）

```python
class FeaturePipelinePort(Protocol):
    def register_feature(self, name: str, func: Callable, input_window: int,
                         params: dict) -> None: ...

    async def compute(
        self, instrument_id: str, interval: str,
        feature_names: list[str], start: datetime, end: datetime,
    ) -> list[FeatureSet]: ...

    async def compute_latest(
        self, instrument_id: str, interval: str, feature_names: list[str],
    ) -> dict[str, float]: ...

    def list_versions(self, feature_name: str) -> list[str]: ...
```

语义要点：

- 特征函数必须是纯函数：`func(bars: list[Bar], params) -> np.ndarray`，禁止 IO；
- **无未来函数校验**：框架校验特征函数只消费截至当前 bar 的数据（按 `open_time` 断言）；
- `compute_latest` 用于实盘关键路径（结果缓存，避免每 bar 全量重算）；
- 特征注册 = 新版本；`register_feature` 相同 name 再次注册视为新版本，旧版本保留。

## 7. 回测引擎端口（BacktestEnginePort）

```python
class BacktestEnginePort(Protocol):
    async def run(self, request: dict[str, Any]) -> BacktestRun: ...
    async def run_batch(self, requests: list[dict[str, Any]],
                        max_workers: int) -> list[BacktestRun]: ...
    async def rerun(self, run_id: str) -> BacktestRun: ...

def build_backtest_request(
    strategy_version: StrategyVersion,
    params: dict,
    instruments: list[str],
    interval: str,
    start: datetime, end: datetime,
    engine_mode: Literal["VECTORIZED", "EVENT_DRIVEN"],
    cost_config: CostConfig,
) -> BacktestRequest: ...
```

语义要点：

- `BacktestRequest` 全字段显式（数据版本、特征版本、撮合模式、成本配置、杠杆/保证金、随机种子）；
- `run` 返回 `BacktestRun`（status=SUCCEEDED 时含 metrics/trades_ref）；失败必须返回 FAILED 记录而非抛异常；
- `rerun(run_id)`：用原请求原环境重跑，结果必须一致（确定性），差异即 bug；
- `run_batch` 并行执行，`max_workers` 受配置上限约束；单任务失败不影响批次其他任务；
- 成本模型（`CostConfig`）：`{maker_fee, taker_fee, slippage_model(FIXED|DEPTH), slippage_bps, funding_rate_source(REAL|FIXED), leverage, margin_mode, liquidation_margin_rate, use_depth_snapshots}`；
- 事件驱动模式必须输出逐笔交易与权益曲线文件引用；向量化模式输出摘要即可。

## 8. 优化器端口（OptimizerPort）

```python
class OptimizerPort(Protocol):
    async def search(self, request: dict[str, Any]) -> OptimizationRun: ...
    async def stop(self, run_id: str) -> None: ...          # 幂等
    async def status(self, run_id: str) -> OptimizationRun: ...
```

语义要点：

- `OptimizationRequest`：`{strategy_version, search_space(dict), objective(name+weights), algorithm(GRID|RANDOM|BAYESIAN|GENETIC), budget(n_evals), walkforward_config, parallel_workers, start(datetime|None), end(datetime|None)}`；
- 搜索过程增量写盘（evaluations 实时可查）；`stop` 优雅终止当前 worker；
- 结果必须含 `best_params` 及其样本外（OOS）指标；
- 随机算法必须接受固定 `seed`（可复现）。

## 9. 策略注册表与生命周期端口

```python
class StrategyRegistryPort(Protocol):
    async def save_version(self, code_pack: dict[str, Any]) -> StrategyVersion: ...
    async def get_version(self, strategy_id: str, version_no: int) -> StrategyVersion: ...
    async def list_versions(self, strategy_id: str) -> list[StrategyVersion]: ...
    async def list_strategies(self, status: str | None = None) -> list[Strategy]: ...

class LifecycleManagerPort(Protocol):
    async def transition(
        self, strategy_id: str, target_status: str,
        evidence_refs: list[str], actor: str, reason: str,
    ) -> dict[str, Any]: ...
```

语义要点：

- `save_version` 幂等（同 `content_hash` 返回既有版本，不重复入库）；版本号自动递增；
- 入库流程：幂等检查 → 静态检查（失败抛 `DataError`）→ params_schema 校验 → 版本号递增 → 写入；
- `save_version` 参数 `code_pack` 为字典，包含 `strategy_id`, `code_ref`, `code_content`, `params_schema`, `data_dependencies`, `feature_dependencies`, `runtime_constraints` 等字段；返回强类型 `StrategyVersion`；
- `get_version` / `list_versions` 返回强类型 `StrategyVersion`；`list_strategies` 返回强类型 `Strategy`；
- `transition` 是状态迁移唯一入口：目标状态非法或无证据 → `ValueError`（带 error_code）；M4 完整实现；
- 每次迁移写 AuditLog 并广播 `LIFECYCLE_TRANSITION` 事件；
- 证据（evidence_refs）必须是实验/报告/部署 ID，禁止空证据升级到 VALIDATED 及以上。

**实现说明**：
- `StrategyRegistry` 使用 SQLite 存储（`data/meta.db`），表结构由 `StrategyRegistry` 内部 DDL 管理（待 M4 接入 `qps.infra.storage.meta_db.MetaDB` 统一管理）；
- `StrategyCodePack` 为内部辅助类，含 `strategy_id`, `code_ref`, `code_content`, `params_schema`, `content_hash` 等字段；
- `isinstance(registry, StrategyRegistryPort)` 为真（协议一致性）。

## 10. 交易链路端口（Signal / Portfolio / Risk / Execution）

```python
class SignalEnginePort(Protocol):
    async def ingest_intent(self, intent: TradingIntent) -> IntentResult: ...

class PortfolioManagerPort(Protocol):
    async def on_intent(self, intent: TradingIntent | CoordinatorIntent) -> list[OrderRequest]: ...
    async def get_allocation(self, strategy_id: str) -> StrategyAllocation: ...
    async def get_portfolio_risk(self, account_id: str) -> PortfolioRisk: ...
    async def merge_positions(self, account_id: str) -> None: ...   # 合并同标同向持仓

class RiskEnginePort(Protocol):
    async def pre_trade_check(self, order_request: OrderRequest) -> RiskCheckResult: ...
    async def on_order_update(self, order: Order) -> None: ...
    async def on_market_update(self, event: Bar | Tick | FundingRate) -> None: ...
    async def register_rule(self, rule: RiskRule) -> None: ...
    async def status(self) -> RiskStatus: ...

class RiskModeControllerPort(Protocol):                    # M4 实现（规则驱动，LLM 不写参数）
    async def apply_event(self, event: NewsEvent) -> RiskModeTransition: ...   # 事件 → 模式映射（静态规则表）
    async def on_market_anomaly(self, detail: dict) -> RiskModeTransition: ... # 行情异常/组合风险触发
    async def get_mode(self, account_id: str) -> RiskModeSnapshot: ...
    async def transition(self, account_id: str, target: RiskMode,
                         triggered_by: str, reason: str) -> RiskModeTransition: ... # 校验滞回规则，非法迁移拒绝
    async def recover(self, account_id: str, actor: str) -> RiskModeTransition: ... # HALT 人工恢复

class CoordinatorPort(Protocol):                           # M7 占位，事件驱动激活
    async def on_trigger(self, context: dict) -> CoordinatorIntent | None: ...  # 输入 NewsEvent/MarketState/持仓/风控状态工件

class ExecutionEnginePort(Protocol):
    async def submit_order(self, order_request: OrderRequest,
                           risk_result: RiskCheckResult) -> Order: ...
    async def cancel(self, deployment_id: str | None = None,
                     instrument_id: str | None = None) -> list[Order]: ...
    async def reconcile(self, account_id: str) -> ReconciliationReport: ...
    async def status(self) -> ExecutionStatus: ...
```

语义要点：

- `ingest_intent`：校验白名单字段、去重限频、有效期检查；拒绝返回 `IntentResult(status=REJECTED, reason)`；
- `on_intent`（Portfolio）：`TradingIntent | CoordinatorIntent` → 一个或多个 `OrderRequest`（仓位合并、精度对齐、余额/权重校验在此完成）；CoordinatorIntent 的目标敞口/风险预算在此换算为仓位调整计划；不通过返回空列表 + 原因（不抛异常）；
- **冲突语义**：`CoordinatorIntent.portfolio_action.reduce_risk=true` 时优先级高于普通策略意图（可打断/覆盖），但仍必须过账户级风控；冲突由 Risk Engine 裁决；
- `pre_trade_check`：**强制同步语义**（即使 async，也必须在下单前完成）；verdict=BLOCK 时 ExecutionEngine 禁止提交；
- `submit_order`：生成 `client_order_id`、调 Broker 提交；`risk_result` 必须为 ALLOW，否则抛 `RiskBlockError`；
- `reconcile`：本地 vs 交易所快照对比，产出差异清单；差异条目 `{field, local, exchange, action_suggestion}`；
- `RiskModeControllerPort`：**确定性入口**——NewsEvent/行情异常/组合风险通过静态规则表映射到模式，迁移必须过滞回校验（防抖、逐级恢复）；`HALT` 只允许人工恢复；每次切换广播 `RISK_MODE_CHANGED` 并落 `RiskModeSnapshot`；
- `CoordinatorPort`：由规则触发（NewsEvent severity 阈值 / regime 变化 / 组合风控状态），禁止 LLM 自我唤醒；输出必须带 `valid_until` 与 `reason_refs`；
- 全链路（5）中任一拒绝都要产生事件与日志，不允许静默丢弃。

## 11. 策略运行时端口（StrategyRuntimePort）

```python
class StrategyRuntimePort(Protocol):
    async def start(self, deployment: Deployment) -> None: ...
    async def stop(self, deployment_id: str) -> None: ...       # 幂等
    async def restart(self, deployment_id: str) -> None: ...
    async def status(self, deployment_id: str) -> RuntimeStatus: ...
```

语义要点：

- 每个 deployment 独立进程/task；`stop` 后未处理意图作废；
- 启动前执行静态检查（见 04 文档），不通过则启动失败并返回原因；
- `RuntimeStatus`：`{status, heartbeat_ts, last_bar_ts, error_count, last_error}`；
- 崩溃自动重启仅恢复进程，不恢复交易权限（需人工确认，见架构 8.4 节）。

class ExperimentStorePort(Protocol):

    async def confirm(self, event_id: str) -> NewsEvent: ...    # 多源一致 → CONFIRMED

语义要点：

- `ExperimentStorePort.compare` 输出同构指标并列表格（含 OOS 列）；
- `MonitoringPort.record` 必须非阻塞（异步队列），禁止阻塞交易关键路径；
- `SchedulerPort.schedule`：JobSpec `{job_type, cron|interval, params, timeout, retry_policy}`；任务执行记录 TaskRun；
- `AgentGatewayPort`：M7 实现，MVP 提供本地 handler 占位；`trigger_type` 区分定时/事件触发，`trigger_ref` 记录触发来源（如事件 ID）；Agent 产出 Artifact 不可变，默认只影响 Draft 状态；
- `NewsCollectorPort`：官方源轮询 30~60s、RSS 60~120s（可配置）；RawNewsItem 含 `{source, title, url, published_at, raw}`；
- `NewsPipelinePort`：规则抽取 = 类型分类 + 资产映射 + 关键词命中；LLM 版只替换 `process` 实现（M7），输入输出 schema 不变；`retract` 必须同步触发 RiskModeController 的滞回恢复评估；
- `NewsEventStorePort`：事件不可变，状态迁移（candidate → confirmed → retracted）通过新版本表达，`list_active` 供 Coordinator 与风控消费。

## 14. v0.5 M0 端口增补

### 14.1 M2 v0.5 Release/Runtime 实现约束

`StrategyRegistry` 的生产实现必须复用 MetaDB canonical `strategies`/`strategy_versions` 表，并持久化可恢复的 `code_content` artifact；不得在 research 模块自建同名 DDL。`ReleaseBuilder` 生成独立 archive、canonical manifest 和 `release_id`，`ReleaseStore.get_release()` 返回前必须校验 archive、代码 hash 和 manifest hash。

`StrategyRuntime` 以 deployment 为隔离单位启动子进程，使用版本化结构化 IPC。子进程只加载 Release archive，不读取可变策略工作目录，不接收 Broker、账户或密钥对象。AST 检查是注册前质量门，不是 OS 级密钥/网络隔离机制。M2 不自动审批、部署或提高交易权限。

v0.5 端口只定义跨所有权边界的签名和一致性语义，不在 `core` 中执行 IO。完整 Protocol 位于 `src/qps/core/ports/v05.py`。

```python
class PointInTimeDataPort(Protocol):
    async def query(self, instrument_id: str, start: datetime, end: datetime,
                    *, decision_time: datetime, manifest_id: str) -> list[Bar]: ...
    async def query_funding_rates(self, instrument_id: str, start: datetime, end: datetime,
                                  *, decision_time: datetime, manifest_id: str) -> list[FundingRate]: ...
    async def query_open_interest(self, instrument_id: str, start: datetime, end: datetime,
                                  *, decision_time: datetime, manifest_id: str) -> list[OpenInterest]: ...
    async def query_mark_prices(self, instrument_id: str, start: datetime, end: datetime,
                                *, decision_time: datetime, manifest_id: str) -> list[MarkPrice]: ...
    async def query_features(self, instrument_id: str, feature_names: list[str],
                             start: datetime, end: datetime, *, decision_time: datetime,
                             manifest_id: str) -> list[FeatureSet]: ...

class ResearchBudgetPort(Protocol):
    async def reserve(self, budget: ResearchBudget, consumption: BudgetConsumption) -> None: ...
    async def consume(self, consumption: BudgetConsumption) -> None: ...

class ReleaseStorePort(Protocol):
    async def save_release(self, release: StrategyRelease) -> None: ...
    async def save_approval(self, approval: ApprovalRecord) -> None: ...

class OrderJournalPort(Protocol):
    async def create_command(self, command: OrderCommand,
                             reservation: RiskReservation) -> None: ...
    async def transition(self, command_id: str, target_status: OrderStatus, *,
                         expected_version: int, observed_at: datetime) -> OrderCommand: ...
    async def record_report(self, report: ExecutionReport) -> None: ...
    async def record_fill(self, fill: Fill) -> None: ...

class LedgerPort(Protocol):
    async def append_account(self, entry: AccountLedgerEntry) -> None: ...
    async def append_strategy(self, entry: StrategyLedgerEntry) -> None: ...

class ReconciliationPort(Protocol):
    async def start(self, account_id: str) -> ReconciliationRun: ...
    async def complete(self, run: ReconciliationRun) -> ReconciliationRun: ...
```

另外提供 `FeatureRegistryPort`、`StrategyHealthPort`、`PortfolioConstructionPort`、`MarketRiskModelPort`、`ChaosScenarioPort`、`BrokerPort`、`AlertPort` 和 `ClockPort`。

M1 的 PIT 实现必须先验证 `manifest_id` 及其 partition 字节 hash，再读取明确引用的文件；不存在 manifest、缺少 `event_time/available_at/ingested_at/close_time/is_closed`、旧无 PIT Parquet 或 `available_at > decision_time` 均失败/不可见，不得回退到目录扫描或当前版本。Feature Engine 只通过该端口获取输入。

`PointInTimeDataPort` 还提供 `query_funding_rates`、`query_open_interest`、`query_mark_prices` 和 `query_features`。这些方法分别要求 supplemental 数据的 `available_at/ingested_at`，funding 另按 `settlement_ts` 做决策时点过滤，feature output 还必须带 `source_manifest_id` 和行级 UTC `decision_time`；后者不得早于 `ts/available_at`，且必须不晚于请求 `decision_time`。缺字段、null、naive 或非 UTC 的旧分区统一抛 `DataError`。正式回测请求必须带 `manifest_id` 和 UTC `decision_time`；缺失时返回失败记录，不得调用 legacy 方法。

上述五类查询还要求每条记录的 `instrument_id`，只返回与请求标的精确相等的记录；`ingested_at < available_at`、非 UTC 或无法解析的 PIT 时间统一抛出 `DataError`，不得跳过坏记录或把请求标的作为默认值。Binance 适配器没有源端可见时间时必须保留未知状态，不能把本地 `ingested_at` 伪装成 `available_at`。

所有 PIT 查询统一校验 `start < end`；逆序、相等、naive 或非 UTC 的请求均以类型化 `DataError` 拒绝。`data compute` 和 `data feature materialize` 的 ISO `start/end/decision-time` 只接受 `Z` 或 `+00:00`，并在初始化数据服务前拒绝非法输入；`research backtest --range` 的两端同样只接受显式 UTC ISO，且在构建容器前拒绝 naive、非 UTC 和逆序范围。`ManifestStore.verify()` 只证明 partition 字节 hash 未变；正式回测、Feature materialization、`data verify` 和 manifest PIT verify 必须继续调用 `verify_pit_manifest(require_formal=true)`，检查 PIT schema、质量报告实体、instrument/interval 覆盖、Feature 行级 decision-time 和 source manifest lineage。

`DATA_STALE`/`DATA_RECOVERED` 状态写入 insert-only `audit_log`，监控启动时重放每个 stream 的最后状态；因此进程重启不会将未恢复的数据默认为健康。

端口一致性要求：PIT 端口不得返回 `available_at > decision_time`；预算预留必须原子且包含失败试验；Release/报告/账本只增不改；OrderJournal 在 Broker 副作用前同一事务写入 command、reservation 和 outbox。状态更新必须以 `command_id + expected_version + from_status` 做原子 CAS，数据库同时拒绝非法 status、非法迁移、旧时间戳和非单调版本；Fill 以 `(venue, account_id, trade_id)` 幂等，终态后的迟到 Fill 只能追加而不能覆盖原订单历史；Broker 超时保留 UNKNOWN 和原 client_order_id；对账完成前不得启用交易。JournalDB 的跨表关系使用 RESTRICT 外键，inbox/order state event/事实表只增不改，预留只允许状态投影，outbox 只允许 `published_at` 投影。

`StringMap` 是递归不可变的字符串键值值对象，但 serializer 必须保持 JSON object 输出；ExecutionReport 的 `raw_payload` 使用专用 `RawJson` 递归不可变值，不能用 `dict[str, Any]` 扩散到核心模型，也不能将嵌套回报压缩成 StringMap。MetaDB/JournalDB 初始化前必须核验 schema contract fingerprint：先剥离 SQL 注释，再将受控 trigger 的完整 canonical `CREATE TRIGGER` 定义规范化并精确比较，保留字符串字面量、WHEN 布尔结构和运算符；SQLite 省略的默认 `FOR EACH ROW` 只在规范化层补入。任一 CAS/预留/outbox/insert-only 语义被删减、改写或藏入注释/字符串都必须拒绝；安全条件变更必须通过新 schema version 和 ADR/迁移。初始化以开始前 SQLite 快照覆盖 legacy rename、DDL、复制、触发器安装、验证和 marker 写入，任一步失败恢复原 schema/data 并抛出带恢复上下文的迁移错误，不写成功 migration 标记。
# M2 v0.5 Formal Execution Contract

正式回测和策略 Runtime 共用 `FormalDecisionInputFactory`、`FormalStrategyExecutor`、strict `StrategyContext` 和 parent-side Intent canonical validation。正式回测请求必须同时绑定 `release_id`、已验证 PIT bars `manifest_id` 和 UTC `decision_time`；该 `manifest_id` 必须等于 Release 内唯一 bars manifest，不能复用于 funding、mark-price 或 feature 查询。引擎从 Release 的 `dataset_manifest_ids` 按 dataset type 路由 funding/mark-price manifest，并从 `feature_set_ids` 对应的 Materialization 路由唯一 feature output manifest；caller 不得注入 supplemental manifest map。`funding_rate_source=REAL` 时必须存在 formal funding manifest；启用 liquidation/mark-price 语义时必须存在 formal mark-price manifest。缺失、候选、重复、跨标的/周期或 hash/quality/lineage 不匹配均失败，不得静默以空集、零 funding 或 bars 替代。DecisionInput、BacktestRun engine config 和审计记录必须保存 Release 解析出的完整 dataset 与 feature lineage。legacy Context/feature callback 只允许显式历史测试适配器使用。

正式 Runtime 的 `execute` 只接受已持久化的 DecisionInput artifact reference，不接受调用方 payload、manifest/feature ID 或 hash。Factory 必须通过真实 ManifestStore/Feature Registry 重新读取并验证 manifest content hash、formal/PIT 状态、quality、source lineage、instrument、interval、materialization 输入/输出 hash，以及 `available_at <= decision_time`；ready 握手不初始化策略。缺失、候选、未来数据、篡改 artifact 或 Release lineage 不一致均 fail-closed。Runtime 与 EventDriven formal backtest 的 DecisionInput、Intent 和 state replay 必须保留相同 reference、canonical payload hash 与 lineage hash。

M2 v0.5 v7 进一步规定：Factory 不得暴露接收 caller `payload`、`available_at` 或 hash 的正式创建 API。
它通过 `PointInTimeDataPort` 从 Release-derived typed source 物化 decision bar 与 feature snapshot，并记录
source-row hash、materializer schema 和 payload hash；`load_verified` 在 Runtime replay 前重新从不可变
PIT source 导出并逐项比较。即使 artifact 的内部 hash 被攻击者一致重算，只要 payload 不能由该
Release/decision-time/instrument/interval 的受信任查询重导，就必须拒绝且不得执行策略或写入 State。

Runtime IPC 的成功结果必须包含已验证的 Intent event、state hash、input snapshot reference 和 lineage；非法字段、错误身份、多个 Intent 或 hash 不一致均为策略级失败。状态由 JournalDB 的 `state_attempts/state_commits` 以 prepare/commit 事务协议持久化，重复输入返回原始 canonical Intent，不重复执行。
