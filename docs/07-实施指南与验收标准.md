# 07 实施指南与验收标准

> 适用：项目负责人 + 开发者。定义 M0~M7 的开发顺序、每个阶段的交付物与验收标准（怎么算「写完」）。
> 里程碑编号与 `prompts/M*.md` 及架构文档 v0.4 第 10 章一致。
> 最后更新：2026-08-03

## 1. 总体原则

1. **按端口契约开发**：先实现 `core/ports` 接口定义（空实现占位），再逐模块实现；禁止先写实现后补接口；
2. **测试先行**：每个模块交付必须带测试（单元/契约/集成），验收以测试通过 + 演示命令跑通为准；
3. **里程碑内闭环**：每个阶段结束时系统可运行、可演示，不允许「代码写了一半」交付；
4. **依赖方向**：core → infra → data/broker → research/trading → control，按此顺序集成；
5. **改动留痕**：接口/字段变更必须同步更新对应文档（docs/01~06）与架构文档，并记录 ADR；
6. **规则优先，LLM 增强**：确定性风险由规则处理（风险模式、事件→模式映射），LLM 只做非结构化理解；M7 前不接 LLM。

## 11. 集成顺序（合并主干顺序）

```
M0: core + infra 合入
  ↓
M1: data 合入（研究可用数据）
  ↓
M2: strategy-sdk 合入
  ↓
M3: backtest 合入（研究闭环演示：3 标的 5m + demo 策略 + ReportCard）
  ↓
M4: trading(portfolio/risk/mode) 合入
  ↓
M5: trading(paper + news 模拟链路) 合入（完整模拟闭环）
  ↓
M6: broker(exchange) + 规则新闻风控真实源 合入（实盘闭环）
  ↓
M7: agents 合入（事件驱动多 Agent 框架，无 LLM）
```

每个里程碑合入前必须：文档更新 + 测试全绿 + 演示命令跑通 + 代码评审。

## 12. 风险提示（开发期）

- **别提前做**：Web 控制台、多交易所、云部署、付费数据、HFT 基础设施、LLM 接入（M7 前）；
- **别绕接口**：发现「图省事直接调内部实现」的 PR 一律打回；
- **别动契约**：接口签名/字段/事件类型修改必须走文档修订 + ADR；
- **确定性优先**：回测任何非确定性（时间、随机、并发顺序）都要显式注入；
- **新闻是增强层**：新闻源故障不得阻塞交易路径；新闻事件不得直接生成订单，只影响风险模式。
