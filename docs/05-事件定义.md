# 05 事件定义

> 适用：系统开发者。事件是模块间解耦的载体，事件 schema 属于稳定契约。
> 最后更新：2026-08-02

## 1. 事件信封（所有事件统一）

```json
{
  "event_id": "evt_<uuid8>",
  "event_type": "ORDER_UPDATED",
  "schema_version": 1,
  "ts": "2026-08-02T12:00:00.123Z",
  "source": "execution_engine",
  "payload": {}
}
```

| 字段 | 说明 |
| --- | --- |
| event_id | 全局唯一，幂等消费依据 |
| event_type | 类型常量（见第 2 节） |
| schema_version | payload 结构版本，升级只增版本不覆盖 |
| ts | 事件产生时间（UTC，本地时钟） |
| source | 产生模块（`data.gateway` / `strategy_runtime` / `signal_engine` / `portfolio` / `risk` / `execution` / `broker.paper` / `lifecycle` 等） |
| payload | 事件体（按类型定义） |

## 2. 事件类型清单

| event_type | 来源 | 消费方 | 说明 |
| --- | --- | --- | --- |
| `BAR_UPDATED` | 行情网关 | 策略运行时、风控、Portfolio | 新 K 线聚合完成 |
| `TICK_RECEIVED` | 行情网关 | 策略运行时（可选） | 逐笔 |
| `FUNDING_UPDATED` | 行情网关 | 策略运行时、风控、Portfolio | 资金费率 |
| `OI_UPDATED` | 行情网关 | 策略运行时 | 持仓量 |
| `MARK_PRICE_UPDATED` | 行情网关 | 风控、Portfolio | 标记价格（未实现盈亏/强平判断） |
| `INTENT_CREATED` | 策略运行时 | Signal Engine | 策略输出意图 |
| `INTENT_REJECTED` | Signal Engine | 监控、策略运行时（反馈） | 意图被拒（含原因） |
| `ORDER_REQUESTED` | Portfolio | Risk Engine | 标准化订单请求（风控输入） |
| `ORDER_UPDATED` | Execution | 风控、Portfolio、监控 | 订单状态迁移 |
| `EXECUTION_REPORT` | Broker | Execution | 成交/状态回报 |
| `TRADE_CREATED` | Execution | Portfolio、监控、审计 | 成交落库 |
| `POSITION_UPDATED` | Portfolio | 监控、风控、审计 | 持仓变化 |
| `ACCOUNT_UPDATED` | Portfolio | 监控、风控 | 账户变化 |
| `RISK_EVENT` | Risk | 监控、审计 | 风控触发（阻断/熔断/冻结） |
| `LIFECYCLE_TRANSITION` | Lifecycle | 监控、审计、策略运行时 | 状态迁移 |
| `TASK_RUN` | 调度器 | 监控 | 任务结果 |
| `ARTIFACT_CREATED` | Agent 网关（M6） | 实验库、监控 | AI 工件 |
| `SYSTEM_HEALTH` | 监控 | 告警 | 系统健康（心跳/延迟/积压） |

## 4. 事件总线语义

| 投递模式 | 用途 | 语义 |
| --- | --- | --- |
| 同步直连（direct） | 交易关键路径：INTENT → ORDER_REQUESTED → ORDER_UPDATED | 同一协程内按序完成，无队列延迟；消费失败向上抛 |
| 异步队列（queue） | 非关键：监控、落盘、审计、回测进度 | 队列隔离，消费失败重试或丢弃并告警（按事件类型配置） |

规则：

- 关键路径事件（BAR_UPDATED → … → ORDER_UPDATED）必须用同步直连，保证「风控不滞后于策略」；
- 所有事件按 `event_id` 幂等消费；消费者必须容忍重复投递（实盘 WS 重连重放场景）；
- 事件必须可序列化（JSON），禁止携带不可序列化对象（如文件句柄）；
- 实盘事件异步落盘 `data/event_logs/<YYYY-MM-DD>.jsonl`（每行一个事件）；
- 事件类型新增 = schema_version 递增 + 本文档更新，禁止静默改 payload 字段。

## 5. 主题（topic）约定

事件总线按 event_type 路由即可（个人单进程场景不需要复杂 topic 树）。预留路由前缀规范（未来拆分进程时用）：

```
market.>       # 行情类
strategy.>     # 策略/意图类
risk.>         # 风控类
execution.>    # 订单/成交类
portfolio.>    # 持仓/账户/组合类
system.>       # 生命周期/任务/健康
agent.>        # AI 工件（M6）
```

*本文件为事件契约基线；事件类型与 payload 修改必须同步升级 schema_version。*
