# 05 事件定义

> 适用：系统开发者。事件是模块间解耦的载体，事件 schema 属于稳定契约。
> 最后更新：2026-08-05

## 1. 事件信封（所有事件统一）

```json
{
  "event_id": "evt_<uuid8>",
  "event_type": "ORDER_UPDATED",
  "schema_version": 1,
  "ts": "2026-08-02T12:00:00.123Z",
  "source": "execution_engine",
  "payload": {}
}
```

| 字段 | 说明 |
| --- | --- |
| event_id | 全局唯一，幂等消费依据 |
| event_type | 类型常量（见第 2 节） |
| schema_version | payload 结构版本，升级只增版本不覆盖 |
| ts | 事件产生时间（UTC，本地时钟） |
| source | 产生模块（`data.gateway` / `strategy_runtime` / `signal_engine` / `portfolio` / `risk` / `execution` / `broker.paper` / `lifecycle` 等） |
| payload | 事件体（按类型定义） |

v0.5 事件规范同时使用 `occurred_at`（事件发生时间）和 `recorded_at`（写入时间），两者必须是 UTC aware，且 `recorded_at >= occurred_at`；`ts` 保留为 v0.4 读取兼容字段。`correlation_id` 和可选 `causation_id` 用于跨模块关联。payload 只接受 JSON 标量、object 和 array，进入信封后递归只读，序列化保持 JSON object/array 结构；`event_id` 是 inbox 幂等键，inbox 与 order state event 只增不改。该只增保护由 trigger 的完整 canonical SQL fingerprint 校验：注释先被剥离，表达式结构和 `RAISE(ABORT, ...)` 保留并与受控 DDL 精确比较，不接受仅同名或把安全条件放进注释/字符串的弱化触发器。

## 2. 事件类型清单

| event_type | 来源 | 消费方 | 说明 |
| --- | --- | --- | --- |
| `BAR_UPDATED` | 行情网关 | 策略运行时、风控、Portfolio | 新 K 线聚合完成 |
| `TICK_RECEIVED` | 行情网关 | 策略运行时（可选） | 逐笔 |
| `FUNDING_UPDATED` | 行情网关 | 策略运行时、风控、Portfolio | 资金费率 |
| `OI_UPDATED` | 行情网关 | 策略运行时 | 持仓量 |
| `MARK_PRICE_UPDATED` | 行情网关 | 风控、Portfolio | 标记价格（未实现盈亏/强平判断） |
| `INTENT_CREATED` | 策略运行时 | Signal Engine | 策略输出意图 |
| `INTENT_REJECTED` | Signal Engine | 监控、策略运行时（反馈） | 意图被拒（含原因） |
| `ORDER_REQUESTED` | Portfolio | Risk Engine | 标准化订单请求（风控输入） |
| `ORDER_UPDATED` | Execution | 风控、Portfolio、监控 | 订单状态迁移 |
| `EXECUTION_REPORT` | Broker | Execution | 成交/状态回报 |
| `TRADE_CREATED` | Execution | Portfolio、监控、审计 | 成交落库 |
| `POSITION_UPDATED` | Portfolio | 监控、风控、审计 | 持仓变化 |
| `ACCOUNT_UPDATED` | Portfolio | 监控、风控 | 账户变化 |
| `RISK_EVENT` | Risk | 监控、审计 | 风控触发（阻断/熔断/冻结） |
| `NEWS_EVENT_DETECTED` | News 管线（规则版/LLM 版） | Risk Mode Controller、Coordinator | 新新闻事件（**高优先级事件通道**，同步直连） |
| `NEWS_EVENT_UPDATED` | News 管线 | Risk Mode Controller、Coordinator、监控 | 事件状态迁移（CONFIRMED / RETRACTED） |
| `RISK_MODE_CHANGED` | Risk Mode Controller | 风控、Portfolio、策略运行时、监控 | 账户风险模式切换（含触发原因） |
| `COORDINATOR_INTENT_CREATED` | Coordinator | Signal/Portfolio | Coordinator 战略层意图（高优先级） |
| `REGIME_CHANGED` | Market Intelligence（规则版，M4） | 策略运行时、Portfolio Manager、Coordinator | 市场状态识别变化（二期 §14，预登记） |
| `MARKET_STATE_UPDATED` | Market State Aggregator（M5） | 策略运行时、Portfolio Manager、Coordinator | 聚合市场状态更新（含 risk_posture / alpha_environment） |
| `ALPHA_DECAY_DETECTED` | Alpha Decay Detection（M5） | Portfolio Manager、Lifecycle Manager | Alpha 连续衰减（二期 §20，预登记） |
| `PERFORMANCE_DEVIATION` | Performance Monitor（M5） | Monitoring、Lifecycle Manager | 实盘表现偏离回测预期（二期 §20，预登记） |
| `STRATEGY_UNDERPERFORMING` | Performance Monitor（M5） | Lifecycle Manager、Monitoring | 多项指标恶化，建议暂停（二期 §20，预登记） |
| `LIFECYCLE_TRANSITION` | Lifecycle | 监控、审计、策略运行时 | 状态迁移 |
| `TASK_RUN` | 调度器 | 监控 | 任务结果 |
| `ARTIFACT_CREATED` | Agent 网关（M7） | 实验库、监控 | AI 工件 |
| `SYSTEM_HEALTH` | 监控 | 告警 | 系统健康（心跳/延迟/积压） |

> 二期事件（`REGIME_CHANGED` / `MARKET_STATE_UPDATED` / `ALPHA_DECAY_DETECTED` / `PERFORMANCE_DEVIATION` / `STRATEGY_UNDERPERFORMING`）按 ADR-006 **预登记**：schema 与语义先入契约，实现分别在 M4/M5/M6 落地；未实现前不允许广播。

## 4. 事件总线语义

| 投递模式 | 用途 | 语义 |
| --- | --- | --- |
| 同步直连（direct） | 交易关键路径：INTENT → ORDER_REQUESTED → ORDER_UPDATED；**防御性高优先级：NEWS_EVENT_DETECTED → RISK_MODE_CHANGED → PORTFOLIO 减仓** | 同一协程内按序完成，无队列延迟；消费失败向上抛 |
| 异步队列（queue） | 非关键：监控、落盘、审计、回测进度 | 队列隔离，消费失败重试或丢弃并告警（按事件类型配置） |

规则：

- 关键路径事件（BAR_UPDATED → … → ORDER_UPDATED）必须用同步直连，保证「风控不滞后于策略」；
- **新闻/风险模式事件必须用同步直连**：`NEWS_EVENT_DETECTED`、`NEWS_EVENT_UPDATED`、`RISK_MODE_CHANGED` 优先级高于行情/信号类事件，可打断普通处理流程（紧急情报不排队）；
- 所有事件按 `event_id` 幂等消费；消费者必须容忍重复投递（实盘 WS 重连重放场景）；
- 事件必须可序列化（JSON），禁止携带不可序列化对象（如文件句柄）；
- 实盘事件异步落盘 `data/event_logs/<YYYY-MM-DD>.jsonl`（每行一个事件）；
- 事件类型新增 = schema_version 递增 + 本文档更新，禁止静默改 payload 字段。

## 5. 主题（topic）约定

事件总线按 event_type 路由即可（个人单进程场景不需要复杂 topic 树）。预留路由前缀规范（未来拆分进程时用）：

```
market.>       # 行情类
strategy.>     # 策略/意图类
risk.>         # 风控类
execution.>    # 订单/成交类
portfolio.>    # 持仓/账户/组合类
system.>       # 生命周期/任务/健康
news.>         # 新闻事件（NEWS_EVENT_DETECTED / UPDATED）
agent.>        # AI 工件与 Coordinator 意图（M7）
```

---

*本文件为事件契约基线；事件类型与 payload 修改必须同步升级 schema_version。*

## 6. v0.5 M0 事件信封与关键事件

v0.5 规范事件信封字段为：

```json
{
  "event_id": "evt_<uuid8>",
  "event_type": "ORDER_COMMAND_CREATED",
  "schema_version": 1,
  "occurred_at": "2026-08-05T12:00:00Z",
  "recorded_at": "2026-08-05T12:00:00.010Z",
  "source": "order_journal",
  "correlation_id": "intent-001",
  "causation_id": "evt-parent",
  "payload": {}
}
```

旧 `ts` 字段由 `EventEnvelope` 保留为读取兼容字段，并映射到 `occurred_at`；新事件必须同时产生两个 typed UTC 时间。`recorded_at` 不得早于 `occurred_at`，`event_id` 必须写入持久化 inbox，不能只依靠进程内集合。

M0 新增关键事件：`DATA_AVAILABLE`、`DATA_STALE`、`DATA_RECOVERED`、`FEATURE_REGISTERED`、`FEATURE_DEPRECATED`、`RESEARCH_BUDGET_RESERVED`、`RESEARCH_BUDGET_EXHAUSTED`、`STRATEGY_DECISION_RECORDED`、`RISK_RESERVED`、`RESERVATION_RELEASED`、`ORDER_COMMAND_CREATED`、`ORDER_SUBMIT_REQUESTED`、`ORDER_STATE_CHANGED`、`EXECUTION_REPORT_RECEIVED`、`FILL_RECORDED`、`FILL_ALLOCATED`、`LEDGER_POSTED`、`RECONCILIATION_STARTED`、`RECONCILIATION_COMPLETED`、`RECONCILIATION_FAILED`、`RELEASE_APPROVED`、`DEPLOYMENT_STARTED`、`DEPLOYMENT_FROZEN`、`STRATEGY_HEALTH_CHANGED`、`RESEARCH_REQUIRED`、`CAPITAL_ALLOCATION_POLICY_APPROVED`、`PORTFOLIO_RISK_UPDATED` 和 `CHAOS_RUN_COMPLETED`。事件只保证至少一次投递，消费者必须幂等；`DATA_STALE` 时不得产生新决策，恢复必须记录 `DATA_RECOVERED`。

正式数据验证必须针对已验证的 manifest；没有 `manifest_id` 时 CLI 不得运行目录型质量扫描。质量报告引用缺失、partition 缺失或 manifest hash 校验失败均为非零失败，不能生成正式验证结果。
### M2 Runtime IPC 与 state lineage

策略 Runtime IPC 使用 `protocol_version=1`，消息必须带 `release_id`、`deployment_id`、`decision_time`、`input_snapshot_ref`；结果带 `intent`、`state_hash`、`audit_hash`。未知消息、身份不匹配、坏 JSON、超限和策略异常均返回错误并冻结对应 deployment，不进入交易事件链路。重复 `input_snapshot_ref` 由 durable state journal 幂等处理。
# M2 v0.5 Runtime State Lineage

Intent event 的 deterministic identity 绑定 `release_id/deployment_id/input_snapshot_ref/canonical_intent`。Runtime 结果经 child SDK 和 parent canonical decode 双侧验证后才可成功。State 先写 `state_attempts`，再在同一 JournalDB 事务写 `state_commits`；提交前崩溃回滚，已提交输入重放返回原始 Intent/State/audit lineage。
