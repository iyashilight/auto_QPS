# 01 项目结构与工程规范

> 适用：所有开发者。先读本节再写代码。
> 最后更新：2026-08-02

## 1. 技术栈基线

| 组件 | 版本/选型 | 用途 |
| --- | --- | --- |
| Python | 3.12+ | 主语言 |
| 数据 | Polars（惰性计算） + NumPy | 特征计算、向量化回测 |
| 模型/校验 | Pydantic v2 | 领域模型与请求/响应校验 |
| 存储 | Parquet + DuckDB + SQLite(内置 `sqlite3` 或 SQLAlchemy 可选) | 历史数据 / 分析查询 / 元数据与状态 |
| 网络 | `websockets` + `httpx`（asyncio） | 实时行情、REST API |
| 任务/并行 | `asyncio` + `multiprocessing` | 调度与回测/优化并行 |
| 测试 | pytest + pytest-asyncio | 单元/契约/集成测试 |
| 质量 | ruff（lint/format）+ mypy | 静态检查与类型检查 |
| 依赖管理 | uv 或 poetry（锁定 lock 文件） | 可复现环境（实验记录需环境锁） |
| CLI | typer 或 click | 控制平面命令行 |

```

├── docs/                        # 本文档集（架构 + 实现规格）

│       ├── core/                # 领域模型、常量、事件、端口（纯定义，无 IO）
│       │   ├── models/          # Pydantic 模型（见 02 文档）
│       │   ├── events.py        # 事件信封与事件类型常量（见 05 文档）
│       │   ├── ports/           # 全部端口（Protocol），见 03 文档
```

约束：

- `src/qps/core/` 下**禁止任何 IO**（不 import 网络、文件、数据库），保证领域模型可被所有模块安全引用；
- `strategies/` 与 `src/` 必须分离：策略是运行时加载的插件，不是系统代码；
- `data/` 整体 gitignore；`configs/` 提交模板，敏感项用环境变量占位。

## 3. 命名规范

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 模块/文件 | snake_case | `event_bus.py` |
| 类 | PascalCase | `ExecutionEngine` |
| 函数/方法/变量 | snake_case | `pre_trade_check` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRY_COUNT` |
| 端口（抽象接口） | 以 `Port` 结尾（Protocol） | `BrokerAdapterPort` |
| 端口实现 | 去掉 Port，体现实现 | `BinanceBrokerAdapter` |
| 枚举 | 类 PascalCase，成员 UPPER_SNAKE | `OrderStatus.FILLED` |
| 内部标识符 | 统一小写下划线，禁止空格/中文 | `btc_usdt_perp` |
| 文档 | 中文 | docstring、注释、README |
| 标识符 | 英文 | 变量、函数、字段名 |

## 4. 代码组织规则

1. **依赖方向**：`control → trading/research → data/broker → infra → core`；`core` 不依赖任何实现；
2. **端口即边界**：跨模块调用只允许通过 `core/ports` 中定义的 Protocol；具体实现由 `di.py` 组装注入；
3. **禁止循环导入**：模块只向上游（core/ports）依赖；发现循环导入 = 设计问题，先修边界再写代码；
4. **函数纯化**：无副作用的计算（指标、特征、撮合判定）写成纯函数，便于测试与并行；
5. **类型注解必须**：所有公开函数签名必须带完整类型注解；模型字段必须带 Pydantic 类型；
6. **不写魔法值**：状态、事件类型、错误码必须引用 `core/constants.py` 或模型枚举。

## 5. 依赖管理与可复现

- 依赖统一在 `pyproject.toml` 声明，锁文件入库；
- 每次回测/优化实验记录环境锁文件路径（或 hash），复跑验证依赖一致性；
- 升级依赖 = 新环境版本，必须重跑基线实验（见 07 文档 M2 验收）；
- 禁止 `pip install` 后不声明（依赖漂移是回测不可复现的头号原因）。

## 6. 测试规范

| 测试类型 | 位置 | 要求 |
| --- | --- | --- |
| 单元测试 | `tests/unit/` | 纯函数、模型校验、状态机迁移 |
| 契约测试 | `tests/contract/` | 每个 Broker/Market/Exchange Adapter 必须通过同一套契约用例（以 Paper Broker 为基准实现） |
| 确定性测试 | `tests/unit/research/` | 同一输入两次回测结果逐位一致 |
| 集成测试 | `tests/integration/` | 事件总线→信号→风控→执行→Paper Broker 全链路 |
| 策略冒烟测试 | `strategies/*/tests/` | 每个策略包自带小样本回测冒烟用例 |

约定：

- 回测相关测试禁止使用随机种子未固定的实现；必须 `seed` 可注入；
- 时间相关测试统一用固定时间（freezegun 或注入 clock）；
- 网络相关测试用本地 mock server（不依赖真实交易所可达性）。

## 7. 错误处理规范

| 异常 | 基类/语义 | 使用场景 |
| --- | --- | --- |
| `QpsError` | 所有业务异常基类，含 `error_code` | 通用 |
| `ConfigError` | 配置加载/校验失败 | 启动阶段 |
| `DataError` | 数据缺失/质量不合格/版本不匹配 | 数据层 |
| `BacktestError` | 回测配置/数据/引擎错误 | 研究系统 |
| `BrokerError` | Broker 层错误基类 | 交易执行 |
| `BrokerAuthError` | 认证失败（密钥过期等） | 适配器 |
| `BrokerRateLimitError` | 限频触发 | 适配器（重试依据） |
| `BrokerNetworkError` | 网络中断/超时 | 适配器（重连依据） |
| `BrokerBusinessError` | 交易所业务拒绝（拒单等），含原始原因 | 适配器 |
| `RiskBlockError` | 风控拦截（非异常流，用于记录但不崩溃） | 风控（建议用返回值而非异常） |

规则：

- 异常必须携带结构化信息（`error_code, detail, cause`），禁止裸抛字符串；
- Broker 层必须把交易所原始错误包装为上述类型化异常，上层只依赖类型做降级；
- 风控拒绝是**正常业务结果**，用 `RiskCheckResult(verdict=block)` 返回，不用异常。

## 8. Git 规范

- 单仓库 monorepo；系统代码 `src/`、策略代码 `strategies/`、文档 `docs/` 同仓；
- 分支：`main`（稳定）/ `feat/*`（功能）/ `fix/*`（修复）/ `exp/*`（实验性，可不合并）；
- commit message 用 Conventional Commits 中文正文：`feat(research): 增加事件驱动回测撮合模型`；
- **策略版本 = git commit + 相对路径**：发布策略版本时记录 commit hash，提交后不修改（如需修改必须新 commit 新版本号）；
- 禁止提交：`data/`、密钥、`.env`、日志、缓存文件（`.gitignore` 必须覆盖）。

## 9. 目录可迁移性（预留小型服务器）

- 系统代码与数据目录绝对分离：`configs/`、`data/`、`src/` 互不耦合；
- 所有路径通过配置注入（禁止代码内硬编码绝对路径）；
- 迁移小型服务器 = 复制 `configs/` + `data/` + 安装环境，系统代码零修改。
